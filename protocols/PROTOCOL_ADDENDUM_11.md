# 补充方案 11：真实任务是否进入同一脆弱次序（预注册草稿）

状态：用户 2026-10-28 批准按本设计运行（"跑吧，多用一些显卡"）；脚本 md5 在第一个正式条件前填入下方。写于 2026-10-28，在任何新任务条件运行之前。目标期刊：Nature Machine Intelligence（结果决定投 NMI 还是别处，见"判定"）。

## 为什么做
补充 8–10 的结论只覆盖 16 个短答案任务（输出 ≤ 32 token）。NMI 审稿最可能的质疑是"这和真实能力有什么关系"。本批回答两个问题：
1. 推理、代码、指令遵循、函数调用这四类真实任务，是否落在同一个、跨损伤一致的脆弱次序里。
2. "受损模型先失去按格式作答的能力、后失去答案"（补充 8：TWICE 错误中 83% 违反模板，其中 79% 仍含正确答案）是否在函数调用这种真实的结构化输出上成立。

## 已知的先验（来自已有数据，写在这里以免事后附会）
- 事后分析 posthoc_v10（未预注册）：
  - 只用完好模型的答案余量与其他模型的格式项预测压缩后的对数指数，中位数 0.70（T10 用同模型随机损伤为 0.81）。
  - 只用前三个剂量（保留 95%/85%/75% 分数）：每个格子的轻度次序与其全程次序一致（中位数 0.915），压缩方法与轻度随机参照一致（0.84）；但单个随机损伤之间两两一致性降到 0.63，层删除参与的配对最低（0.33–0.35），且 56 个格子中只有 37 个在轻度区可测。
- 补充 8 的探索性 GSM8K 思维链测度（100 题、种子 0/1）：在 35 个格子中位于 67% 的测度之后失效，19 格中 18 格比四数相加的短答案更耐。

## 设计

### 模型与条件（复用已锁定的剂量，不重新标定）
- 模型：Qwen2.5-7B（q7）、Llama-3.2-3B（llama）、Mistral-7B（mis）、Gemma-2-9B（gemma）。
- 损伤：
  - noise：补充 8 锁定的 8 个剂量，种子 1、2。
  - wanda：补充 9 锁定的 8 个剂量。
- 每个模型在其补充 8/9 原来的服务器与软件栈上运行，使受损权重与原条件逐位相同（llama 的 noise 在 server_b，其余全部在 server_a）。
  - 校验：每个条件施加损伤后先跑一遍固定探针（atlas_full.Probe，64 段固定文本），其 NLL 须与存档条件的探针 NLL 相差不超过 0.1%；不符的条件标记 check_ok = False，不进入分析，并停下排查。（草稿原写"重跑 ARITH2_BARE 与 SCIQ_CHOICE 并要求准确率完全相同"，改为探针：只跑两个任务会改变分批，bf16 数值的微小差别可能翻转个别题，不能当逐位相同的判据；探针的分批固定。）
- 由此，新任务的指数可以直接投影到原格子已估计的损伤强度 h(d) 上，与原来的 64 个测度放在同一把尺子上，不需要重新拟合格子。

### 新任务（每个 200 道评测题，一次生成后冻结并记哈希）
| 代号 | 能力 | 来源 | 作答 | 判对 |
|---|---|---|---|---|
| GSM_COT | 多步推理 | GSM8K 测试集（与补充 8 同一洗牌，前 100 道即原探索性题目） | 简短思维链后写 "The answer is N."，最多 384 token | 与补充 8 的 judge_cot 相同 |
| CODE | 写代码 | HumanEval（164 题全用）+ MBPP sanitized 补到 200 | 只输出一个 Python 函数，最多 384 token | 在隔离子进程中跑官方单元测试，10 秒超时，全过为对 |
| IFEVAL | 指令遵循 | IFEval 全部 541 道中去掉 384 token 内写不完的长度要求（至少 200 词以上、12 句以上、4 段以上），剩 488 道，抽 200 | 自由作答，最多 384 token | IFEval 官方检查器，strict 口径，全部约束满足为对 |
| FCALL | 函数调用（结构化输出） | BFCL v3 "simple" 类别（单函数），抽 200 | 只输出 JSON：{"name": ..., "arguments": {...}}，最多 128 token | 格式：整段回复（允许外包一个代码围栏）可解析为恰含 name 与 arguments 两键的对象，参数名都属于函数 schema；内容：函数名正确，每个参数值属于可接受答案（类型须一致，数字 1 与 1.0 等价，字符串按 BFCL 规范化比较；可接受答案含空串的参数可省略）；两者都满足为对 |

- 机会水平全部取 0。可用规则与补充 8 相同（完好时机会校正后分数 ≥ 0.4）。
- FCALL 额外记录宽松内容分：从输出中任意位置抽出的函数名与参数值是否正确，不要求合法 JSON。用于检验"先坏格式"。

### 指数
- 对新测度 m 与格子 (模型, 损伤)：取原格子的 h(d)（analyze9.fit_cell 在原 64 个测度上估计，本批不改），在窗口 0.03 < c < 0.97 内用过原点最小二乘求 n_m = Σ h·(−log c) / Σ h²，至少 2 个点。
- 与原测度用同一个归一化常数（原格子的几何均值），因此新旧测度可以直接比较。

## 检验与判定（写在运行之前）
- **N1 次序跨损伤一致（核心）**：每个模型内，全部可测测度（原 64 个中已拟合的 + 新 4 个）的对数指数在 noise 与 wanda 之间的 Pearson 相关；4 个模型的中位数。并且每个新测度在两种损伤下的分位位置（在全部测度中的百分位）相差 ≤ 25 个百分点的比例。
  - 成立：中位数 ≥ 0.7，且分位位置一致的新测度比例 ≥ 75%。
- **N2 新任务可被两因子预测**：用补充 8 的加性模型（任务项 + 格式项，四种随机损伤上拟合）无法覆盖新任务；改为检验新任务的指数是否落在原测度的范围内（第 5 到 95 百分位之间）。只描述，不进入判定。
- **N3 先坏格式（函数调用）**：在 FCALL 的相对完好分数落在 0.3–0.7 之间的剂量上（每个模型 × 损伤取最接近 0.5 的一个剂量，noise 两个种子合并），只看完好时答对、受损后答错的题，统计其中格式失败（不可解析或 schema 不符）的比例，以及格式失败中宽松内容仍出现的比例。另比较 FCALL 严格分数与宽松内容分数的指数比。
  - 成立：格式失败占错误的中位数 ≥ 50%，其中宽松内容正确的中位数 ≥ 50%，且指数比（严格 / 宽松）中位数 ≥ 1.5。
- **判定**
  - N1 与 N3 都成立：投 NMI，主张扩展为"真实任务也在同一次序中，结构化输出先于答案失效"。
  - 只有 N1 成立：投 Nature Communications 或 NeurIPS，主张为"真实任务也在同一次序中"，格式先坏只在短答案任务上成立。
  - N1 不成立：投 TMLR，主张收窄为"短答案任务的共同次序"，新任务结果如实报告为范围限制。

  - 运行中（gemma 19/25 时）曾用锁定脚本做过一次中期计算，当时已算出 N1 不可能成立（3 个完整模型已有 5 个不一致，上限 11/16）；最终结果与中期一致。

- **N2（描述）** 见 analysis12.json。
- **判定（按预注册规则）**：TMLR。主张收窄为"短答案任务的共同次序"；真实任务如实报告——指令遵循跟随共同次序，多步推理的位置随损伤类型系统性移动（剪枝下更脆，4 个模型中 3 个），函数调用上"先坏格式、后坏答案"得到确认。
