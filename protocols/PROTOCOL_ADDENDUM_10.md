# 补充方案 10：逐 token 余量能否解释脆度（预注册）

写于 2026-10-28，在采集任何逐 token 余量之前。目标期刊：Nature Machine Intelligence。

## 坦白在先
- 被预测的量（补充 8、9 中各测度的脆度指数）已经存在，我们看过。这个假设是在看过"格式效应很大、TWICE 的错误多为违反模板"之后提出的，属于事后提出的假设。
- 用来预测的量（完好模型的逐 token 余量）是新采集的，写本文件时还一个都没测过。检验的效力来自这一点：预测量在锁定分析之后才产生，分析脚本在采集前锁定 md5，之后不改。

## 假设（余量机制）
损伤近似于给模型的输出打分加噪声。一个测度何时失效，取决于完好模型产生合格输出所需的每一个决策点上的余量；需要做对的决策越多、余量越薄，越早失效。若成立，它同时解释任务项（答案本身的余量）与格式项（格式需要更多、更薄的决策）。

## 采集（margins.py，只在完好模型上运行，不施加任何损伤）
对每个模型、每个任务（16 个）、每个生成格式（BARE、JSON、TWICE）、每道评测题（300 道）：
1. 用与补充 8 完全相同的提示（atlas_full.chat + body）、贪心解码、最多 32 个新 token，重新生成。
2. 每一步记录：所选 token、该步 logit 前 5 名之间的差（第 1 名减第 k 名，k = 2…5）。生成在模型的轮次结束 token 或 32 步处停止；轮次结束 token 那一步计入。
3. 用 atlas_full.judge 判对，记录重新生成的输出是否与补充 8 存下的完好输出逐字相同（报告一致率）。

CHOICE 格式不需新采集：补充 8 的完好结果已存每个候选的求和对数概率；margins.py 只补记每个候选 continuation（候选 + 轮次结束）的 token 数。

## 噪声模型与预测（analyze11.py，固定、无自由参数）
设损伤强度为 σ，每个候选（生成时的每个 token；CHOICE 时每个候选序列中的每个 token）的对数分数独立加上 N(0, σ²/2) 的噪声，因此任意两个单 token 分数之差的噪声标准差为 σ。

- **生成格式的一道题**：在关键步 j 上保持正确所选的概率 = ∏_{k=2..5} Φ(δ_jk / σ)，δ_jk 为第 1 名与第 k 名的 logit 差（独立近似）。一道题存活 S(σ) = 各关键步之积。
- **关键步（主分析）**：
  - BARE：从第 1 步到最短的、已被 judge 判对的前缀为止（答案写完之后的输出不影响判对，因为 BARE 只判第一行的答案内容）。
  - JSON、TWICE：全部步，直到并包括轮次结束 token（模板之后多写任何东西都会使模板匹配失败）。
- **CHOICE 的一道题**：S(σ) = ∏_{干扰项 k} Φ( Δ_k / (σ·√((L_g + L_k)/2)) )，Δ_k = 正确候选与干扰项 k 的求和对数概率之差，L 为各自的 token 数。
- **测度的预测曲线**：只用完好时判对的题，ĉ_m(σ) = 这些题 S(σ) 的平均（失效的题回到机会水平，与补充 8 的机会校正一致）。
- **预测指数**：σ 取 0.01 到 100 之间对数等距的 60 个值；对每个模型的全部可用测度，用 analyze9.rank1 在相同窗口（0.03 < ĉ < 0.97）、相同"至少两个点"的规则下拟合秩一模型，得到 n̂_m，同样归一到几何均值 1。σ 的绝对尺度在归一后不起作用，因此没有任何从受损数据拟合的参数。

## 被预测的量
每个模型内，测度 m 的观测对数指数 = 四种随机损伤（noise、zero、neuron、ld_rand）中拟合出该测度的各格子的 log n 的平均，要求至少两种损伤拟合出该测度。指数取自 analyze9 的 fit_cell（与补充 8、9 相同）。主分析用补充 8 的 7 个模型；32B 与三种压缩方法单独报告（次要）。

## 检验与判定（写在采集之前）
- **M1 主检验**：每个模型内，log n̂ 与观测 log n 在共同测度上的 Pearson 相关；7 个模型的中位数。
- **M2 任务部分（格式之内）**：每个模型 × 每个格式（至少 6 个任务）内，log n̂ 与观测 log n 的相关；全部格子的中位数。
  - 基线 B2：现有的答案余量预测（该任务完好 CHOICE 余量的平均，取负），同样在格式之内计算。
- **M3 格式部分**：对 log n̂ 做与 analyze9.additive 相同的任务 + 格式分解，得到预测的格式项 β̂。计算 β̂ 的次序与观测次序（CHOICE < BARE < JSON < TWICE）完全一致的模型数；并报告预测与观测的 TWICE 减 CHOICE 之差。
- **M5 只看长度的对照**：把每个模型的全部 δ（含 CHOICE 的 Δ）换成该模型全部 δ 的中位数，其余不变，重算 M1–M3。这检验"决策点的数量"本身能解释多少。

**判定（主分析，7 个模型）**
- **押（余量机制成为正文主线）**：M1 中位数 ≥ 0.80，且 M3 次序完全一致的模型 ≥ 6，且 M2 中位数 ≥ B2 中位数。
- **部分成立（写成"格式效应来自需要做对的决策数量与余量"，任务项仍以答案余量解释）**：M1 在 [0.65, 0.80)；或 M1 ≥ 0.80 且 M3 成立但 M2 < B2。
- **停（余量机制不进入主线，在附录报告为否定结果）**：M1 < 0.65，或 M3 次序完全一致的模型 < 4。
- **措辞规则**：若 M5 的 M1 与主分析之差 < 0.03，机制写成"需要做对的决策数量"，不写成"余量"。

**敏感性分析（不影响判定，全部报告）**：关键步改为"全部步"；只用前 2 名的差（只算第 1 名与第 2 名）；去掉补充 9 中的四个极端任务（COPY、RETR、FACT、ARITH3）。

## 计算
8 个完好模型（7 个 + 32B），每个一遍生成（3 个格式 × 16 任务 × 300 题，最多 32 步），量与一次完好评测相当。每个模型在其补充 8 完好结果所在的服务器上运行（server_a：q7、q14、mis、gemma；server_b：q15、llama、phi、q32），以使重新生成的输出尽量与存档一致。只在空闲且不在保留名单上的卡上运行。

## 采集前的冒烟测试与执行说明（2026-10-28，正式采集之前）

## 结果（2026-10-28，analyze11.py md5 64e3129647d59a4e11e010dc015be3fe，7 个模型；输出 analysis11.json）
- 与存档逐字一致率：q15、q7、mis、phi 1.000；q14 0.982；gemma 0.982；llama 0.959。
- M1 中位数 0.459（0.39–0.60）；M2 中位数 −0.034，基线 B2（答案余量）0.796；M3 次序完全一致 3/7。
- 只看长度的对照：M1 0.363。敏感性：全部步 0.430、只用前 2 名 0.408、去掉极端任务 0.589，均未改变判定。
- 压缩方法（次要）：M1 中位数在 0.06–0.75 之间，多数 < 0.5。
- **判定：停。** 余量机制不进入正文主线，在附录报告为否定结果。

描述（不影响判定）：逐 token 余量在格式之内几乎不预测任务次序（M2 ≈ 0），远不如答案层面的求和对数概率余量（0.80）；在格式之间，它把 JSON 预测为最脆（模板 token 多、单步余量不大），而观测中 JSON 接近中间、TWICE 最脆。即"每个关键步独立受噪声扰动"的模型不成立：模板 token 在损伤下远比其单步余量所示更耐，TWICE 的脆弱也不来自步数。
