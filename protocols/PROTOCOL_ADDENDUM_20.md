# 补充方案 20：知识轴与格式轴能否分开（预注册，只用现有数据）

写于 2026-10-30，在计算任何 JSON、TWICE 格式下的频率—存活关系之前。用户当日批准（"试试呗"）。

## 起因
结果部分想写成三个轴：任务、知识、格式。任务与格式的可分性已有（加法模型 89%）。知识（答案在预训练语料中的熟悉度）只在 BARE 格式下检验过，没有证据表明它与格式相互独立。本方案检验两点：知识效应是否在每种格式下都在；格式的先后是否在常见与少见答案中都一样。

## 已看过的数据（如实说明）
- 补充 14、15、16 的 BARE 格式频率效应（首都 0.423、SciQ 0.383；每种损伤下 0.23–0.41）。
- 正文的格式顺序（Choose < Answer < JSON < Twice）及首都、SciQ 在各格式的完好准确率（例如 q15 的 SciQ TWICE 完好只有 0.05、不可用）。
- 没有看过任何 JSON、TWICE 格式下的逐题频率—存活关系，也没有看过按频率分半后的格式顺序。

## 数据与量（analyze22.py）
- 逐题数据 analysis15_cache.pkl；频率 freq15.json（首都共现）、freq16.json（SciQ 答案计数）。不改动。
- 存活分：某模型在全部 7 种损伤、全部剂量与种子上的平均正确率（与补充 14–16 相同）。首都按国家合并（要求该国全部题在该格式下完好答对）。
- 只用可用量；一个格子至少 30 个单位。

## 检验与判定
- **H1 知识效应不随格式变（主检验）**：BARE、JSON、TWICE 各自在全部有效格子（最多 8 模型 × 2 任务）上 Spearman(log 频率, 存活) 的中位数与为正比例。每种格式要求有效格子 ≥ 8、中位数 ≥ 0.20、为正 ≥ 75%（与补充 16 的单损伤门槛相同）。
  - 押：3 种格式全过；部分：BARE 与另一种过；停：其余。
- **H2 格式顺序不随知识变（主检验）**：在 BARE、JSON、TWICE 都完好答对的单位上，按格子内 log 频率中位数分成少见半与常见半；每半内比较三种格式的平均存活。
  - 押：有效格子 ≥ 8，且 ≥ 75% 的格子在两半内都满足 BARE ≥ JSON ≥ TWICE；
  - 部分：不满足押，但 ≥ 75% 的格子在两半内 TWICE 都最低；
  - 停：其余。
- **结构决定**：H1 与 H2 都押 → 正文写三个可分开的轴（任务、知识、格式）。否则维持"两个轴加任务内部的知识"，并写明知识效应在哪些格式下成立。

## 结果（analysis22.json）
- **H1 知识效应不随格式变：押（3/3）。** 全部有效格子为正（100%）。
  - BARE 中位数 0.396（16 格；首都 0.423，SciQ 0.383，与补充 14、15 一致）。
  - JSON 0.365（16 格；首都 0.448，0.210–0.514；SciQ 0.323，0.132–0.432）。
  - TWICE 0.211（11 格；首都 0.246，0.121–0.383；SciQ 只有 3 个模型可用，0.177）。TWICE 刚过门槛，效应约为 BARE 的一半。
- **H2 格式顺序不随知识变：押。** 11 个有效格子（8 个首都、3 个 SciQ）全部在少见半和常见半内都满足 BARE ≥ JSON ≥ TWICE（100%）；phi 首都的 JSON 与 TWICE 相等。其余 5 个 SciQ 格子因 TWICE 不可用或三格式同时答对的题少于 30 道而不计。
- 结构决定：按预注册写法，正文写三个可分开的轴（任务、知识、格式）。
- 需如实交代：在最脆的 TWICE 格式里知识效应变弱（约一半），即格式坏得多时，熟悉度的作用被压低；三轴是近似独立，不是完全独立。H2 主要靠首都（SciQ 只有 3 个模型可检验）。
